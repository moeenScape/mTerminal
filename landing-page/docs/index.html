Get started with mTerminal.

Install the app, start a local shell or SSH session, and open a remote folder.

Install mTerminal

Linux

On Debian or Ubuntu, install the .deb package from the Downloads page when one is published. Run this from the directory containing the installer, using its exact filename. 

sudo apt install ./mterminal_0.1.0_amd64.deb

To build the Debian package from a source checkout, use Node.js 24.12 or later within Node 24 and npm 11. Install the native build tools required by the project, then run these commands from the repository root. 

npm ci
npm run dist

Open mTerminal from the application menu after installing the package from apps/desktop/dist/.

macOS

Check Downloads for a published installer for Apple Silicon or Intel. macOS packaging and signing are pending in the current project. Platform support is tracked in the development roadmap.

Windows

Check Downloads for a published Windows installer. Windows packaging and verification are pending in the current project.

Open a local shell

Open Workspace and choose New local terminal. Select a shell available on your machine, then open additional tabs or split the current workspace to keep sessions in view.

Connect over SSH

  1. Open Hosts, add a host, and enter its name, server address, SSH port, and username.
  2. Choose Connect. Enter your credentials or select an available saved identity.
  3. Verify the server’s host-key fingerprint through a trusted source before accepting it. A successful connection opens a tab in Workspace.

Use groups to organize saved hosts and apply shared defaults where needed.

Browse and transfer files

  1. Open Files from a connected SSH terminal tab. The left pane is your computer. The right pane is the remote host.
  2. Select a file and choose Upload or Download. Review the destination before confirming the transfer.
  3. Use Back to terminal to return to the same shell.

The remote server must allow both a shell and SFTP for this workflow.

Manage saved credentials

Set up and unlock the local vault to save supported SSH passwords or managed private keys. Create a reusable identity in Hosts to use the same authentication settings with multiple hosts.

Keep a separate copy of credentials you need for recovery. Workspace exports contain profile data and exclude saved credentials.
